# jav-site

Site for the Journey Against Violence (JAV) organization, a Liberian rehabilitation program for former child soldiers, drug addicts, and criminals.

## Design Principles

**Simplicty**: The site should be extremely simple to read, navigate, and understand.
**Mobile First**: The site should be mobile-first.
**Responsive Design**: Ensure the site is responsive and works well on all devices.

## Coding Principles

**Type Safety**: Write type safe code to ensure correctness wherever possible.
**Don't Repeat Yourself**: Don't unnecessarily redefine constants, helpers, and types locally if they could reasonably be used elsewhere. Derive types from existing types, including library types if applicable, wherever possible.
**Conciseness**: Keep code and any wording concise and to the point.
**Reduce comments**: Avoid comments unless required to explain unusual or complex logic. JSDoc is acceptable but keep it minimal.

## Development Workflow

pnpm workspaces, Node >= 22.12.

### Commands

- **dev** — `pnpm dev`
- **deploy** — site: `pnpm build` then `pnpm --filter site deploy` (the deploy script is bare
  `wrangler deploy`, so an un-built `dist/` ships stale). Studio: `pnpm --filter studio deploy`.
- **typecheck** — `pnpm typecheck`
- **lint** — `pnpm lint` / `pnpm fix`
- **codegen** — `pnpm codegen` after any Sanity schema or GROQ change

## Architecture

Three workspace packages:

- **`apps/site`** — Astro, Cloudflare adapter. Everything prerenders; there are no server routes.
- **`apps/studio`** — Sanity Studio. Deployed separately, never bundled into the site build.
- **`packages/content`** — the boundary between the two. GROQ queries, TypeGen output, and the
  `@sanity/client` factory.

### Conventions

- Routing lives in code (`src/pages`), Sanity owns copy. `nav` in `src/lib/site.ts` is the header.
- Content-managed pages are the `page` document type, served by `src/pages/[slug].astro`.
- Native HTML first (`<details>` for the FAQ, `<dialog>` for modals), then plain `.astro`. No
  framework islands are wired up — add one only when a component needs real client state.

### Known tooling quirks

- Biome parses `.astro` frontmatter only, not template markup, so `noUnusedVariables` is off for `.astro`.
- `apps/site/worker-configuration.d.ts` is generated by `pnpm --filter site cf-types` and gitignored.
  Cloudflare secrets are declared by hand in `apps/site/src/env.d.ts` — `wrangler types` cannot see them.
- GROQ queries must be wrapped in `defineQuery()` from `groq`, or TypeGen silently finds 0 queries.
- TypeGen output is committed and `overloadClientMethods` is on, so `client.fetch(SOME_QUERY)` is typed
  from the query string with no type argument. There is no runtime validation: stale generated types
  typecheck clean against a changed Studio schema, so run `pnpm codegen` after any schema or GROQ change.
- GROQ projections return `null` for absent fields, never `undefined`. Handle `null`.
- The content client sets `useCdn: false` on purpose. Builds are triggered by the publish webhook and
  the API CDN caches for ~60s, so a CDN read can build the site from pre-publish content.
- Astro scopes class selectors but not `@keyframes` names — prefix keyframe names per component.
- `apps/site/wrangler.jsonc` is **not** the deployed config. The adapter regenerates
  `dist/server/wrangler.json` from it at build time and wrangler deploys that — always
  `pnpm build` after editing `wrangler.jsonc`, or your change is silently dropped.
